Dense Linear Algebra (BLAS / LAPACK)

AppleAccelerate forwards BLAS and LAPACK calls to Apple's Accelerate framework via Julia's libblastrampoline (LBT) mechanism. This happens automatically when the package is loaded, unless you turn automatic forwarding off.

How it works

On __init__, AppleAccelerate loads both LP64 and ILP64 BLAS/LAPACK interfaces from Accelerate. OpenBLAS remains as a fallback for operations not provided by Accelerate (e.g., gemmt).

Since Accelerate provides a full BLAS and LAPACK implementation, all standard Julia LinearAlgebra operations are accelerated transparently. This includes:

Factorizations: lu, qr, cholesky, svd, eigen, schur, ldlt, hessenberg, and their in-place ! variants

Solvers: \, ldiv!, rdiv!

Matrix operations: mul!, *, det, tr, inv, pinv, rank, norm, cond, opnorm

BLAS routines: All Level 1 (vector), Level 2 (matrix-vector), and Level 3 (matrix-matrix) operations via LinearAlgebra.BLAS

For the complete list of available operations, see the Julia LinearAlgebra documentation.

Using the package without changing BLAS

BLAS/LAPACK forwarding is global: it changes what every LinearAlgebra call in the session runs on. If you only want the other subsystems (vDSP, vImage, libSparse, BNNS, …), turn automatic forwarding off and the session's BLAS is left untouched:

using AppleAccelerate
AppleAccelerate.set_auto_forward!(false)   # writes LocalPreferences.toml; restart Julia

or, for a single process, set the environment variable before the package is loaded:

APPLEACCELERATE_AUTO_FORWARD=0 julia

The environment variable takes precedence over the preference. With automatic forwarding off, forwarding becomes an explicit opt-in:

using AppleAccelerate, LinearAlgebra
X = AppleAccelerate.fft(randn(ComplexF64, 1024))   # vDSP; BLAS is still OpenBLAS
AppleAccelerate.load_accelerate()                  # now forward BLAS/LAPACK to Accelerate

AppleAccelerate.set_auto_forward!(true) restores the default.

AppleAccelerate.load_accelerate — Function
load_accelerate(; clear = false, verbose = false, load_ilp64 = true)

Load Accelerate, replacing the current LBT forwarding tables if clear is true. clear is false by default to allow for OpenBLAS to act as a fallback for operations missing from Accelerate, such as gemmt. Attempts to load the ILP64 symbols if load_ilp64 is true, and errors out if unable.

AppleAccelerate.auto_forward_blas — Function
auto_forward_blas() -> Bool

Return whether AppleAccelerate forwards BLAS/LAPACK to Accelerate automatically when the package is loaded. The default is true. It can be turned off, in order of precedence, by

  • the environment variable APPLEACCELERATE_AUTO_FORWARD (0/false/no/off to disable, 1/true/yes/on to enable), read when the package is loaded, or
  • the auto_forward_blas preference, set with set_auto_forward!.

With automatic forwarding off, loading AppleAccelerate leaves the session's BLAS/LAPACK untouched; call load_accelerate to forward explicitly.

source
AppleAccelerate.set_auto_forward! — Function
set_auto_forward!(flag::Bool)

Persistently enable (true, the default) or disable (false) automatic BLAS/LAPACK forwarding on package load, by writing the auto_forward_blas preference to the active project's LocalPreferences.toml. Takes effect the next time AppleAccelerate is loaded, i.e. after restarting Julia. See auto_forward_blas.

Disable it to use the non-BLAS parts of the package (vDSP, vImage, libSparse, BNNS, …) without changing the session's BLAS; load_accelerate then forwards on demand.

AppleAccelerate.set_num_threads — Function
set_num_threads(n::Integer) -> BlasInt

Select Accelerate BLAS threading mode. This is a toggle, not an exact thread count: n == 1 selects single-threaded mode, while n > 1 selects Accelerate-managed multi-threaded mode (Accelerate chooses the actual number of threads). Returns the resulting thread count as reported by get_num_threads, which for the multi-threaded mode is Accelerate's chosen count rather than n. On macOS < 15 where the threading API is unavailable, warns and returns 1.

source
AppleAccelerate.get_num_threads — Function
get_num_threads() -> BlasInt

Return the number of threads used by Accelerate BLAS. Returns 1 for single-threaded mode, or the actual thread count for multi-threaded mode. On macOS < 15 where the threading API is unavailable, warns and returns 1.

get_macos_version()

Return the current macOS version as a VersionNumber. Returns nothing on non-Apple platforms or if the version cannot be determined.

source
AppleAccelerate._read_macos_version — Function
_read_macos_version()

Read the macOS version from the system plist and return it as a VersionNumber. Early macOS Tahoe betas reported version 16.x before Apple finalized the version numbering as 26.x; this function normalizes 16.x → 26.x for correct comparisons. Returns nothing on non-Apple platforms or if the version cannot be determined.
